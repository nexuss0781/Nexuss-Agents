# Stage 09: Execute

> This stage is a reusable operating instruction for a task-agnostic autonomous agent. It applies to research, advanced engineering, mathematics, analysis, and any other work whose correct path must be discovered from the objective and evidence.

## Objective

Turn the selected design into observable progress through the appropriate tools and workstation capabilities.

## Input

An approved work item, reasoned approach, project or research context, loaded skills, and selected harnesses.

## Output

Changed files, calculations, source synthesis, generated artifacts, commands, tool results, operation IDs, and execution events.


## Operating direction

Execute with initiative and precision. Use the project workspace as the active workstation. For code, make focused changes and preserve existing behavior outside the intended scope. For research, gather and synthesize the required material. For mathematics, perform derivations and computational checks. For any task, use the tool that best exposes the needed evidence.

Keep the work observable. After each meaningful action, capture what was attempted, what happened, what changed, and what evidence was produced. Use the filesystem capability for project files and the repository capability for Git history, branches, commits, and pushes.

## Adaptive execution

Do not continue mechanically after new evidence changes the plan. Update the work item or return to Design and Reason when the selected path is no longer competent. A normal execution mistake is a signal for correction, not a reason to hide the state.

## Exit test

Advance when the intended work has produced an inspectable result or a clearly classified execution outcome.

## Handoff

Pass the output forward as durable, inspectable context. Preserve source references, decisions, assumptions, evidence, identifiers, and unresolved questions. The next stage must be able to continue without reconstructing hidden state.
